# API contract — `matchday-agent`

Frozen in Phase 0. **`matchday-mcp-web`** (Svelte 5 on Vercel) is the
sole first-party consumer and treats these shapes as a stable contract.
Any breaking change requires bumping the API version prefix (currently
none — v1 is implicit) and coordinating with the web repo.

## Endpoints

| Method | Path            | Purpose                                     | Rate limit         |
|--------|-----------------|---------------------------------------------|--------------------|
| GET    | `/`             | Version + model + tools count (about page)  | unlimited          |
| GET    | `/health`       | Wake probe (Fly.io + external monitors)     | unlimited          |
| GET    | `/openapi.json` | Auto-generated OpenAPI schema (FastAPI)     | unlimited          |
| POST   | `/chat`         | Non-streaming JSON in/out (tests + evals)   | 20 req/min per IP  |
| POST   | `/chat/stream`  | SSE — primary path for the web              | 20 req/min per IP  |

## Common request shape

`POST /chat` and `POST /chat/stream` both accept:

```json
{
  "message": "¿Cómo llega el Real Madrid al clásico?"
}
```

And require:

| Header          | Value                                                       |
|-----------------|-------------------------------------------------------------|
| `Content-Type`  | `application/json`                                          |
| `X-Session-Id`  | UUID v4 generated by the web client, stored in `localStorage`. Used verbatim as LangGraph `thread_id` for the Postgres checkpointer. Invalid UUIDs → 400. |
| `Accept`        | `application/json` (`/chat`) or `text/event-stream` (`/chat/stream`) |

## `POST /chat` — non-streaming response

```json
{
  "message": "El Real Madrid llega al clásico con …",
  "sources": [
    { "kind": "tool",       "tool": "get_team_matches", "input": { "team": "Real Madrid" } },
    { "kind": "tool",       "tool": "get_top_scorers",  "input": { "competition": "PD" } },
    { "kind": "rag",        "title": "El Clásico",       "url": "https://en.wikipedia.org/wiki/El_Cl%C3%A1sico" }
  ],
  "session_id": "…",
  "usage": { "prompt_tokens": …, "completion_tokens": …, "total_tokens": … }
}
```

Errors — plain JSON with a machine-readable `code`:

```json
{ "code": "rate_limit_exceeded", "message": "20 requests per minute allowed", "retry_after": 60 }
```

## `POST /chat/stream` — SSE event contract

Response headers:

```
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
Transfer-Encoding: chunked
```

Event types (each `event:` line is followed by a `data:` line whose
payload is JSON):

### `event: token`

Streaming tokens from the model. Concatenate `text` in order to
reconstruct the running answer.

```
event: token
data: {"text": "El "}

event: token
data: {"text": "Real "}
```

### `event: tool_call`

Emitted when the agent decides to invoke a tool. `id` is a stable
per-call identifier that the matching `tool_result` will echo.

```
event: tool_call
data: {"id": "call_01H…", "tool": "get_team_matches", "input": {"team": "Real Madrid"}}
```

### `event: tool_result`

Emitted after the tool returns. `ok=false` indicates the tool signaled
an error (e.g. `find_team` couldn't resolve the name); the agent may
still recover.

```
event: tool_result
data: {"id": "call_01H…", "ok": true, "summary": "5 matches — form: WWDLW"}
```

### `event: final`

Sent exactly once at the end, containing the fully assembled answer
plus the same `sources` shape as `POST /chat`. After `final`, the
server MAY close the stream; the client SHOULD treat any subsequent
events as noise.

```
event: final
data: {"message": "El Real Madrid llega al clásico …", "sources": [ … ]}
```

### `event: error`

Any unrecoverable failure. Terminates the stream.

```
event: error
data: {"code": "upstream_llm_timeout", "message": "Groq did not respond within 30s"}
```

### `event: ping` (optional)

If a call takes > 10 s before the first `token`, the server MAY emit
`ping` events every 5 s to keep intermediate proxies from closing the
connection. Payload is a `{"ts": <unix_ms>}` object. Clients MUST
ignore unknown fields.

## Session semantics

- `X-Session-Id` is treated verbatim as the LangGraph `thread_id`.
- State persists across process restarts (Fly.io machine auto-stops
  and cold-starts) because `AsyncPostgresSaver` writes to Supabase.
- Sending the same message twice on the same session id will result in
  the second call seeing the first call's completed state as history.
- Clients rotating session ids get fresh state.
- No cross-session read protection in v1 (no auth). Guessing another
  client's UUID lets you read their state. Documented as a known
  limitation; revisit before opening to the public beyond the demo web.

## CORS

Only origins listed in `ALLOWED_ORIGINS` (comma-separated env) may
call the API from a browser. `/health` also honors this (no wildcard).
Non-listed origins → CORS preflight 403, browser aborts.

## Versioning

- v1 is implicit (no `/v1/` prefix).
- Any change to the SSE event names, the JSON keys of `data:`
  payloads, or the request/response shapes is **breaking** and must
  introduce `/v2/` alongside. Additive fields (new optional keys in
  `data:` payloads) are backward compatible.
